# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html) (`MAJOR.MINOR.PATCH`).

## [Unreleased]

### Removed
- The MGMB mesh format (`MeshBinaryIO`, `docs/MGMB_FORMAT.md`) is removed. MGOM (`.omb`) is the only mesh persistence format. `.mgmb` files are no longer read or written by the CLI or the WebUI; the CLI reports that they must be converted with an earlier release. Breaking change for files saved with MGMB.

### Added
- Heat conduction, two-dimensional thin plate (core): `OpenModel::Heat2D` in `include/OpenModel/Heat2D.hpp`. Plate with circular or rectangular holes on a structured grid of bilinear quadrilaterals (holes by element centroid, staircase boundary); temperature, flux and convection-radiation conditions on the sides and on the hole boundaries; transient and steady, theta method, consistent or lumped capacity, Picard iteration for temperature-dependent conductivity and radiation, conjugate-gradient solver. Formulation, verification and limits: `docs/HEAT_2D.md`. Test: `tests/heat2d_test.cpp` against exact linear fields, a double Fourier series, the transient sine mode and the Kirchhoff transform. Script `analysis heat 2d` in `include/OpenModel/Heat2DScript.hpp` (plate, material, holes, side conditions, hole condition, source, initial temperature, steady or transient step), with line-numbered errors; test `tests/heat2d_script_test.cpp`. Not yet in the CLI or GUI. Conduction on linear triangle meshes, steady and transient (`OpenModel::Heat2D::solveMesh`, `include/OpenModel/Heat2DMesh.hpp`), with an annulus generator through Gmsh (`meshAnnulusGmsh`) and import of a STEP file with one planar face (`meshPlanarStepGmsh`), both in `include/OpenModel/Heat2DGmsh.hpp`, Gmsh backend only. Tests `heat2d_mesh_test` and `heat2d_gmsh_test`. Mesh script `analysis heat 2d mesh` (`include/OpenModel/Heat2DMeshScript.hpp`): reads a STEP planar face, meshes it with Gmsh and solves it; runner `runMeshScript` in the Gmsh backend; line-numbered errors. Tests `heat2d_mesh_script_test` and `heat2d_mesh_run_test`.
- Viewer: opacity of the geometry. A slider in View (Opacity, 5 to 100 %) makes the surfaces translucent, so the edges and the points inside them are visible; `OpenModelViewer.set({opacity})` sets the same level. The surfaces are not depth-sorted: overlapping translucent faces may blend in any order. Test: `tests/webgl/viewer_opacity_smoke.js`.
- Heat conduction 1D: display of the geometry. "Show geometry" draws the real cross-sections of the segments, one colour per material, and the axis as a black tube of radius a percentage of the model size (2 % by default). After a run, "Show results" colours the elements by the 1D temperature at their position along the axis (`OpenModel::Heat1D::displayMesh`, the `openmodel_heat1d_show` handler). The drawing does not change the structural model. Tests: `tests/heat1d_display_test.cpp`, `tests/webgl/gui_heat1d_smoke.js`.
- Heat conduction, 1D along the axis (core, script and GUI panel "Heat 1D" in the Analysis tab, not yet in the CLI): transient and steady conduction on a segment with linear finite elements, variable cross-section, temperature-dependent conductivity, volumetric source, lateral and end convection and radiation, temperature and heat-flux ends, theta time integration (explicit, Crank-Nicolson, implicit), consistent or lumped capacity, Picard iteration for the non-linear terms. Core: `OpenModel::Heat1D` in `include/OpenModel/Heat1D.hpp`. Script `analysis heat 1d` (sections: rectangle, circle, tube, regular polygon, table; one or more materials along the axis, each segment with its own elements, interfaces on nodes; conductivity constant (`k=`) or tabulated in temperature (`kT=T1:k1,T2:k2,...`)) in `include/OpenModel/Heat1DScript.hpp`, with the internal solver only. The solver takes explicit node positions (`Model::nodes`). Formulation, simplification ladder, script syntax and verification results: `docs/HEAT_1D.md`. Tests: `tests/heat1d_test.cpp` against closed forms and the discrete energy balance; `tests/heat1d_script_test.cpp` for the sections, the commands and the error messages. Segments may carry their own simple section (`shape=rect|circle|tube|polygon`), so a chain of primitives is a list of segments. The GUI panel has a primitive-chain builder that writes the material and segment lines, and edits the rest of the script as text (every command is listed in its help), runs it through the handler `openmodel_heat1d_run`, shows the temperature along the axis for each recorded time and downloads the CSV; it does not change the structural model. Not compared yet with CalculiX or another code.
- Solvers: several solvers can be configured, each with a kind (`calculix`, `code_aster`, `elmer`) and an executable path, and the default solver of each analysis type (static, frequency, dynamic) can be chosen. A job names its solver with `job NAME solver=ID` in the analysis script; without it the job uses the default of its type. The Analysis panel picks the solver of a run and the Settings table lists the solvers. The built-in ids `calculix`, `code_aster` and `elmer` are always present. Settings files of the earlier version (one `solverPath`) are read as the solver `calculix`. Core: `OpenModel::SolverConfig`, `solverForJob()` in `include/OpenModel/Solvers.hpp`. Tests: `tests/solvers_test.cpp`, `tests/workbench_settings_test.cpp`.
- Elmer: a static analysis can run with ElmerSolver. The export writes the mesh in the ElmerSolver directory format and the solver input `<job>.sif`: volume blocks become bodies with their materials (per part as in `assign`), fixes become point elements with Displacement conditions, pressures become Normal Force on the faces of the surface group, and gravity becomes a body force. CLI: `openmodel export-elmer <mesh> <analysis.txt> <dir> [--job NAME]`, and `openmodel solve ... --elmer <path>` runs the jobs whose solver is Elmer. GUI: a run with an Elmer job launches ElmerSolver and reports the end of the run; the results are not read into the viewer yet. Refused for Elmer, with a message: nodal forces, distributed loads, rigid links, time-dependent loads, frequency and dynamic steps, several steps per job. **Not verified**: ElmerSolver is not available where this was written, so the case files follow the Elmer manual as remembered and have not been solved; see `docs/SOLVER.md`.
- Analysis script: named tables of (time, factor) pairs (`table name=T1 t=...`). An amplitude takes its points from a table (`amplitude name=A t=T1`), and a job can give another table to an amplitude (`job NAME amp=A:T2`), so one load can have a different time history in each job. Tables and amplitudes must be defined before use. The GUI creates, edits and removes tables (*Time dependence* → *Tables*), with the same rules as the parser; a table in use cannot be removed or renamed, and an amplitude can take a table by name. Job overrides are text only in the GUI. Pasting several values into the table dialog fills the rows from values separated by blanks, tabs, line breaks, commas or semicolons (the decimal separator is the dot). GUI test: `tests/webgl/gui_tables_smoke.js`. Parser and deck tests in `tests/analysis_setup_test.cpp` (`testTables`). Docs: `docs/SOLVER.md`.
- Viewer: the increments of a transient run (and of a static run with several load increments) are shown as a time history. The web view binds the displacement of every increment as a frame (at most 100, sampled evenly, first and last kept); the "Increment" slider steps through them and "Play" runs them at five per second, while the scalar fields stay those of the selected step. The default frame is the selected step. The MGWV format gains `frames` and `frame` (see `docs/MGWV_FORMAT.md`). Core: `WebFrame`, `WebViewOptions::frames`/`defaultFrame`, `BindOptions::timeHistory`/`maxFrames`. Tests: `fem_results_test` (binding, sampling, writer validation), `solver_cli_dynamic` with its `solver_cli_dynamic_frames` check, `tests/webgl/viewer_frames_smoke.js`.
- GUI: the left panel can be folded away with the Panel button at the right end of the ribbon, which gives the whole window to the viewer. The choice is kept between sessions. Test: `tests/webgl/gui_session_smoke.js`.
- Viewer: a results bar on the right lists the fields and the modes of the model. A click on a field shows it in scalar colouring; a click on a mode selects it. The bar folds to its title, and the choice is kept. It is a section, so it stays visible in the embedded viewer. Test: `tests/webgl/viewer_results_bar_smoke.js`.
- GUI: New model (File > Session) closes the current model: the server drops its CAD, meshes, results and analysis, the viewer, the model trees and the Analysis script are emptied. It asks for confirmation first and is refused while a solver runs. The materials and the tessellation deflections are kept. Handler: `openmodel_close_model`. Test: `tests/webgl/gui_session_smoke.js`.
- GUI: Settings (File > Session) keeps three values: the solver path, the jobs folder and the legend palette. The jobs folder has a folder chooser ("Use this folder"). The settings are saved in `settings.json` in the user configuration folder (`$XDG_CONFIG_HOME/openmodel` or `~/.config/openmodel`; `%APPDATA%\OpenModel` on Windows) and are read by the server, so they apply to every run. The solver path is used when the Executable field of Analysis is empty and is the same for CalculiX and code_aster: set it to the executable of the solver in use. Relative job paths and the default job (`openmodel_job/job`) are relative to the jobs folder. Core: `src/webui/WorkbenchSettings.hpp`. Test: `tests/workbench_settings_test.cpp`.
- Viewer: the palette, scale and range controls of the colour bar can be hidden and shown with a button, and the choice is kept between sessions. The colour bar itself stays visible. The colour bar background is transparent. Viewer session API: `clear()`, `palettes()`, `palette()`, `setPalette()`, `setLegendOptions()`. Test: `tests/webgl/viewer_legend_smoke.js`.
- Viewer: the colour bar of the results is on the left of the viewer and is vertically centred. It has five palettes (Viridis, Rosso, Ocra, Blu, Arcobaleno), a linear or logarithmic scale (the logarithmic scale needs a positive minimum: otherwise the linear one is shown with a note), editable Min and Max that follow the sidebar inputs, and three intermediate ticks. Test: `tests/webgl/viewer_colorbar_smoke.js`.
- Distributed loads: `distributed group:NAME F=fx,fy,fz [amp=NAME]` shares a total force over the faces of a surface group in proportion to their area. Core: `OpenModel::DistributedLoad` (`AnalysisModel::distributed`), written as nodal `*CLOAD` by the CalculiX writer, refused by code_aster. GUI: the Distributed button in the Selection ribbon creates the face group from the selected faces and adds the line; the Loads list shows, edits and removes it. Tests: `tests/analysis_setup_test.cpp` (conservation of the total, area shares, amplitude, errors), `tests/webgl/gui_dist_load_smoke.js`.
- Project archive: `OpenModel::exportProjectArchive()` and `importProjectArchive()` (`ProjectArchive.hpp`) pack the project manifest and every asset into one ZIP file with all entries stored, uncompressed. The import checks every CRC-32 and recorded SHA-256 and rejects unsafe names. CLI: `openmodel project-export` and `openmodel project-import`. Test: `tests/project_archive_test.cpp`.
- Jobs, steps and loads are persisted as part of the analysis script (`analysis.model` asset); the archive carries it with the mesh.
- GUI: Log section in the sidebar. It shows the messages that the operations write to the console (the volume mesh, the CAD import and tessellation, the Gmsh and TetGen messages), while they run: the page reads them every 0.7 s from `openmodel_log_since`. Filter by level (Errors, Warnings, Information, Debug, the same levels as the Gmsh log), Clear (this page only) and Save (text file). The OpenModel phases are always recorded; the Gmsh details follow the Gmsh log level, read after each meshing step, so the progress is shown by phase and not by percentage. Tests: `tests/webgl/gui_log_smoke.js`, `tests/progress_log_test.cpp`.
- Rigid links (RBE2): `rbe2 group:NAME ref=x,y,z` couples the nodes of a node group to a reference node (CalculiX `*RIGID BODY`): the six degrees of freedom of the nodes follow the reference node. The reference node is created in the deck with the next free id. Core: `OpenModel::RigidLink::group` (the slaves are resolved from the group when the deck is written), parsed and serialized with the script. GUI: the RBE2 button in the Selection ribbon creates one node group and one rigid link per hole: the selected faces are split into holes (faces that share nodes), and the reference node of each hole is its centre (a circle fit with deviation at most 5 %), otherwise the centroid of its nodes. Several holes are made in one action. Handlers: `openmodel_rbe2_reference` (one line per hole), core `sharedTokenClusters()`. Links built from node indices without a group are not written to the script. Viewer: each rigid link is drawn as a red dot on its reference point and red segments from it to the coupled nodes (shown with the "fixed dofs" switch, clipped with the section); Fit frames the reference points too. The MGWV descriptor has `rigidLinks` (coordinates in the file frame). Viewer API: `rigidLinks()`. Tests: `tests/rigid_link_test.cpp` (script round trip, group resolution, missing group), `tests/web_view_writer_test.cpp` (rigid link coordinates in the file frame).
- Core: `OpenModel::ProgressLog`, a thread-safe log with sequence numbers and a capacity (5000 entries by default); `parseGmshLogLine()` reads the Gmsh log lines. The CLI and the console output are unchanged.

### Changed
- The solver runner no longer refuses Windows: `ProcessRunner` runs through `TK4CPP::Process`, which has a Windows implementation (Job Object). Not built or run on Windows yet. README (Requirements, TK4CPP, known limits) and `docs/SOLVER.md` updated accordingly.
- Solver processes run through `TK4CPP::Process` instead of the hand-written fork/exec and CreateProcess code. `OpenModel::ProcessRunner` keeps its interface. `cancel(seconds)` now sends SIGTERM and kills the process when the grace period given by the caller has passed, measured by ProcessRunner itself. Test: `tests/process_runner_test.cpp` (output order, exit codes, working directory, cancel with and without a SIGTERM handler, death by signal, double start, missing program). The test passes under ThreadSanitizer.
- The base64 decoder of the WebUI drop of files uses `TK4CPP::Encode::Base64` with its default options. Test: `tests/web_base64_test.cpp`.
- CMake: `OPENMODEL_TK4CPP_SOURCE` chooses between downloading TK4CPP (`FETCH`, default) and an installed TK4CPP (`INSTALLED`). See the README section TK4CPP. A `FETCH` build installs an OpenModel package without TK4CPP.
- Project manifest: asset paths are written as UTF-8 with `TK4CPP::Utility` (`pathToUtf8`). Before, they were written with `generic_string()`, which on Windows gives the local code page, while the reader expects UTF-8: non-ASCII asset paths did not round-trip there. **Compatibility:** a manifest written on Windows by an earlier build with a non-ASCII asset path is read back with a different name. Linux manifests are unchanged. Test: `tests/openmodel_project_test.cpp` (UTF-8 asset path, Linux only). Temporary file names of the manifest and of the assets come from `TK4CPP::Utility::UUIDHandler::Generate_V4`.
- `openmodel_core` and `openmodel_shared` now compile as C++23 when they use TK4CPP (TK4CPP requires C++23). `OpenModelProject.cpp` uses `std::filesystem::path` from UTF-8 bytes in C++20 and later, since `u8path` is deprecated there.
- Viewer: rotation about each axis with the left button and a modifier key. Ctrl+Alt+drag rolls (about the view axis), Ctrl+Shift+drag pitches (about the horizontal axis), Shift+Alt+drag yaws (about the vertical axis). Each drag uses only the component that drives its axis (horizontal for roll and yaw, vertical for pitch). The modifier drags do not select, and Ctrl+Alt no longer starts a rectangle selection. Plain drag and Shift+drag (pan) are unchanged. Test: `tests/webgl/viewer_rotation_axes_smoke.js`.
- GUI: the Log moved from the bottom of the sidebar to a panel at the bottom of the window, with the Log and Solver tabs (the solver output left the Analysis section). The panel can be hidden and resized; its state is kept between sessions.
- GUI: status bar at the bottom: the counts of the shown mesh, the latest message of the backend (kept after Clear), and the version.
- GUI: the Selection controls moved from the top of the sidebar to a card over the viewer (same controls, the card can be collapsed).
- GUI: each category of the model tree shows its state beside its name: CAD imported, mesh count and nodes, constraints, load cases, jobs with or without results.
- Viewer: overlay on the canvas with the section plane (on/off, X/Y/Z, flip, position) and the display mode (Hidden, Surface, All). The controls drive the existing inputs of the sidebar, so the state stays in one place.
- Viewer: colour bar on the canvas for the scalar field colouring, with the field name and the range in use (it follows the Min and Max inputs).
- Viewer: results card at the top right of the canvas, for a file with results: the load case, the mode and its frequency, the component coloured, the deformation factor and the largest displacement shown (value and percentage of the model size).

## [0.1.5] - 2026-11-20

### Added
- GUI: drag and drop of a CAD file on the 3D viewer adds it to the model, as Import CAD does. The viewer posts the dropped file to the OpenModel window, which sends its content (base64) to the new handler `openmodel_import_cad_upload`; the file is stored in `openmodel-cad/` in the temporary directory under its own name, so the CAD face groups saved next to it keep working. `.mgwv` files dropped on the viewer are still loaded there. Test: `tests/webgl/viewer_cad_drop_smoke.js`; `base64` decoding in `src/webui/Base64.hpp`. Not compiled here (WebUI and OpenCASCADE absent): the C++ side is untested.
- GUI: Mesh branch. The meshes of the session are listed under Mesh; the eye shows one in the 3D viewer, the × removes it from the session (if it was shown, the last mesh left is shown). The backend keeps them in a `MeshRunRegistry` and replaces a run with the same name and counts instead of listing it twice. Handlers: `openmodel_mesh_runs`, `openmodel_mesh_select`, `openmodel_mesh_remove`. Tests: `tests/webgl/gui_mesh_runs_smoke.js`, `gui_tree_smoke.js`.
- Core: rigid links for holes. `RigidLink` couples mesh nodes to a reference point through CalculiX `*RIGID BODY` (all six degrees of freedom); the reference is created in the deck at the given point. `fitHoleCircle()` fits a hole edge, `holeRigidLinks()` makes one link per hole with warnings `RBE2_OFF_AXIS` and `RBE2_NOT_CIRCULAR`. The writer refuses a node in two links. Test: `rigid_link_test`. Not verified with a real CalculiX run; no script syntax or GUI yet.
- Core: MeshRunRegistry keeps the meshing runs of a session (whole assembly or one part), with one active mesh; only the active mesh is shown, solved and exported. Not yet connected to the WebUI.
- GUI: Material per part. The Material panel lists the volume parts of the mesh with the material each one takes (the default unless assigned); the choice is written to the script as an `assign` line. The Material branch of the sidebar lists the parts under it. Editing or removing an additional material works (`updateMaterial` and `eraseMaterial`; removing it drops the assign lines that use it). Test: `tests/webgl/gui_part_materials_smoke.js`, plus the core test `testPartMaterials`.
- Materials per part: the analysis script takes further `material id=...` lines and `assign PART material=ID` lines. Each volume part (mesh block) gets its material; parts without an assign use the first `material` line (the default). The CalculiX deck has one `*MATERIAL` per material and one `*SOLID SECTION` per part. `AnalysisModel` gained `materials`, `partMaterials`, `findAnalysisMaterial()` and `materialForPart()`. code_aster refuses more than one material. Scripts with one material give the same deck as before. Test: `testPartMaterials`. The GUI does not list the parts under Material yet.
- Bodies of the mesh: `MeshBody` (name, dimension 3 or 2, elements) in `MeshData::getBodies()`. Gmsh records the top-level CAD entities as bodies and meshes each one in the dimension given by `MeshingOptions::bodyDimensions` (a shell is always a surface). `exportableMesh()` (MeshBodies.hpp) is the export rule: a volume body is exported with its volume elements only, a surface body with its surface elements. Applied by `AbaqusInpWriter::writeFile()` and `writeCodeAsterMesh()`; the viewer and the native MGMB store keep every element. Test: `mesh_bodies_test`. The Gmsh part compiles and the Gmsh test suite passes (Gmsh 4.15 SDK, `OPENMODEL_BUILD_GMSH_BACKEND=ON`), but no test checks the bodies of a Gmsh mesh yet.
- CAD face sizing (Gmsh, opt-in): `MeshingOptions::cadFaceSizeFactor` gives each non-planar face (and each planar face below `cadSmallFaceLength`) a size of factor times sqrt(area) through Distance and Threshold fields. Off by default: measured on the models in the repo, it gives no clear gain over the default sizing and costs much more time (OilPan at factor 1.0 on the non-planar faces: element quality 0.244 against 0.233, 40 times the meshing time). Test: `gmsh_structured_test` (`checkCadFaceSizing`).
- GUI: the Gmsh mesh structure can be chosen between structured (default, unchanged) and unstructured tetrahedra. The unstructured controls are the thin-face factor, the CAD face sizing factor and the length for planar faces, and the dimension of each CAD body (`3,2,3`, one entry per top-level body). The web backend reads them as arguments 14 to 18 of `openmodel_generate_volume`. Checked: the page logic in headless Chromium (visibility, argument order) and the body-dimension parser (unit cases). The WebUI backend is not built here (no WebUI SDK): its code was only syntax-checked against a stub header.
- Analysis jobs and steps: `job NAME` lines, `step ... loads=A,B reset` and `findJob()`, `activeLoadIds()`; the CalculiX deck has one `*STEP` per step, zeroes the loads with `reset` and writes the supports once. Tests: `testJobsStepsAndLoads`.
- Results of transient (dynamic) runs: every increment is a separate time step, already read before; now the choice is by time as well as by index: `openmodel export-web ... --time T` and `t=T` in the GUI step field take the increment nearest to T. The GUI step message no longer stops at 30 steps (long histories show the first 20 and the last 10). Test: `testDynamicIncrements` (25 increments) and `fem_results_cli_time`.

### Changed
- GUI: the sidebar is one collapsible tree (CAD, Mesh, Material, Constraints, Load cases) replacing the two branches. Each category has an eye for the 3D viewer (Mesh: mesh groups, Constraints: constraint symbols, Load cases: deformed shape; CAD also has the axes) and a "+" that opens its first action. Under Material there is one eye per material, which hides the groups that carry it. The CAD eye hides the surface blocks (CAD geometry) and keeps the volume mesh; the viewer gets a `blockOn` option in `set()` for it.
- GUI: the details of the selected tree node open in an overlay over the viewer and close with × or Escape; they no longer sit under the tree.
- GUI: the model tree is essential: every node starts closed; Mesh lists the meshes of the session, Constraints the fix lines, Load cases the loads, and a Jobs node shows each job with its steps and the loads each step uses, read from the analysis script.
- Viewer: the constraint symbols are less intrusive: default size 2.2 % of the model radius (was 3 %), cones about a third thinner (base radius 0.28 of the size, was 0.42) and smaller rotation rings. The size is still adjustable in the viewer panel.
- Analysis model: the loads are defined once and jobs select them per step. `AnalysisModel::jobs` holds `AnalysisJob`s (one solver session each) whose `AnalysisStep`s set the analysis type, the active loads (`loads=`) and whether the loads of the earlier steps are zeroed (`reset`). The step fields `step`, `modes` and `dynamic*` moved from the model to `AnalysisStep`. `writeSolverInput()` and `writeCodeAsterCase()` take the job name (not needed for a model with one job). Scripts without `job` lines behave as before.
- CLI: `write-input` writes one deck per job (`<job>.inp`), `solve` runs one solver session per job. `--web` needs a single job.
- Version raised to 0.1.5.

## [0.1.3] - 2026-11-14

### Added
- `openmodel-fatigue` command-line tool: `analyze` (one or more positions of a FEM result, reports in CSV and JSON), `spectrum` (ordered blocks of several result sets with repetitions, reports in CSV and JSON) and `info`. Inputs are JSON: material curves (`stressLifeSN` or `strainLifeEN`, with explicit units), positions (`node:ID`, `element:ID`, `ip:ELEMENT:N`) and spectrum files. Result units are declared with `--unit SYMBOL:SCALE` or `resultUnit`, because CalculiX files do not declare one.
- `OpenModel::Fatigue::Json`: a strict, small JSON reader used by the fatigue input files.
- Constraints on the degrees of freedom of the nodes in the FEM data structure: `MeshData::constrainNode()`, `constrainNodes()`, `releaseNode()`, `clearConstraints()`, `constraintOf()`, `getConstraints()` and the counts, with a mask of the six degrees of freedom (`NodeDof`, `DofMask`: ux, uy, uz, rx, ry, rz) and a prescribed value for each; checked by `validate()`. They are stored by MGMB 1.2 (a mesh without constraints is still written as 1.1), imported from the Abaqus/CalculiX `*BOUNDARY` blocks (including `ENCASTRE`, `PINNED` and the symmetry types, `MeshImportOptions::importConstraints`), written back as `*BOUNDARY` by `AbaqusInpWriter`, and `supportConstraints()` / `applySupports()` resolve the `fix` supports of an analysis to node constraints.
- Viewer and GUI: the constraints are drawn at the nodes (MGWV `constraints` chunk, `WebViewOptions::includeConstraints` and `extraConstraints`): a double cone along each fixed translation (X red, Y green, Z blue), a ring around each fixed rotation, an orange dot where a value is prescribed; they follow the deformation and the section plane. `Constraints` checkbox, `Symbol size` (% of the model radius), `OpenModelViewer.set({ constraints, constraintSize })` and `OpenModelViewer.constraints()`. The GUI also draws the supports of the analysis script and rebuilds the view when the analysis changes, keeping the camera. Tests: `mesh_constraints_test` and the headless `viewer_constraints_smoke.js`.
- Viewer and GUI: a triad of the model axes (X red, Y green, Z blue) in the bottom left corner of the view. It follows the rotation of the model (orthographic, from the camera rotation only, so it ignores zoom and pan); axes pointing away from the viewer are thinner and fainter. `Axes` checkbox, `OpenModelViewer.set({ axes: true|false })`. Test `viewer_axes_smoke.js` compares the arrows with the screen directions of real nodes, in the standard views and after rotating with the mouse.
- Fixed: in the analysis script the `id=` of a condition was not recognised when it was not the first token of the line, so the GUI edited it by line and not by identifier.
- Desktop GUI: complete constraint cycle. Select nodes, elements or faces in the viewer, tick the degrees of freedom to block (ux, uy, uz, rx, ry, rz, with optional prescribed values) in the *Mesh constraints* panel and press *Apply to selection* (also the ribbon button *Constrain* on the Analysis tab). The constraint is set on every node of the selection (`selectedNodes()`, mid-side nodes of faces included). *Release on selection* and *Remove all constraints* undo it; the list shows the constraint classes. Host handlers `openmodel_constraint_apply`, `_release`, `_clear`, `_list`.
- `OpenModel::selectedNodes()` (MeshSelection.hpp): sorted node indices of a viewer selection.
- Mesh constraints reach the solver: `writeSolverInput()` and `writeCodeAsterCase()` call `withMeshConstraints()`, which turns the translation constraints stored in the mesh into fixed supports (`mesh-constraint-N`, one per set of blocked translations and values; conflicts with the script are refused). Rotations are dropped with the warning `CONSTRAINT_ROTATION_IGNORED`.
- Time-dependent loads and dynamic analysis in the script: `amplitude name=A t=t1,f1,t2,f2,...` defines a piecewise factor; `amp=NAME` on `force` and `pressure` multiplies the load by it (written as `*AMPLITUDE` and `*CLOAD`/`*DLOAD, AMPLITUDE=`); `step dynamic dt= period= [dtmin= dtmax=]` writes `*DYNAMIC`. The GUI Load cases tab adds the amplitude, the amplitude field of the loads and the step. Refused by code_aster for now. Moments, body forces, centrifugal loads and tractions are not written yet (see docs/SOLVER.md).
- Known materials: `OpenModel::MaterialLibrary` keeps the built-in materials (read-only) and the personal ones, which can be added, changed and removed. They are saved to `materials.tsv` in the user configuration folder (`%APPDATA%\OpenModel` on Windows, `~/.config/OpenModel` elsewhere; the environment variable `OPENMODEL_MATERIALS` sets another file). A file that cannot be written undoes the change. The Material tab of the GUI lists them, edits them and writes the chosen one into the script.
- Built-in database of linear elastic materials (`OpenModel::materialDatabase()`, 30 entries: aluminium alloys, structural and stainless steels, cast iron, copper, brass, titanium, magnesium, concrete C25/30 to C50/60, spruce and oak along the grain, common polymers, glass, alumina, granite). Values are typical or code values, stored in SI; `materialScriptLine()` writes a script line in SI or in mm-t-s. The Material tab of the GUI picks an entry, in the units chosen there.
- Face selection in the viewer and in the GUI: holes are recognised. A click on a face of the wall of a hole (a bolt hole, a bore, a pin seat) selects the whole wall: the faces that make a concave cylinder around an axis, found as the smooth patch around the clicked face that fits a cylinder (axis from the face normals, circle fitted to the vertices, radial deviation within 3 %), wraps around the axis by at least `Hole arc` degrees (default 330, a closed hole; 170 also takes half of a hole cut by a symmetry plane) and has no material on the side of the axis. A convex cylinder (a boss, the outer wall of a ring) and a plane are never taken for a hole; a fillet or a chamfer at the mouth of the hole is left out. Controls `Holes` and `Hole arc` in the viewer and in the GUI, `OpenModelViewer.pick.setHoles` and `setHoleArc`. Face angle 0 selects a single face and does not look for holes. Tests `viewer_hole_smoke.js` on a washer and half a washer, as hexahedra and as tetrahedra with mixed winding.

### Changed
- Version raised to 0.1.3.
- Desktop GUI: the sidebar is organised in tabs (CAD, Mesh, Material, Constraints, Load cases), each with collapsible sections. The selection options stay on top, visible from every tab. A Material form sets the material line of the script; the Constraints and Load cases tabs list the fix and load conditions of the script separately.
- Face selection in the viewer and in the GUI: a click on a face now also selects the connected faces on the same plane (`Face angle`, default 1 degree instead of 0), so a whole planar face of the model is picked with one click, to apply constraints or other bulk operations to its nodes. The angle is the angle between the planes of two faces (0 to 90 degrees; 0 selects only the clicked face), and it no longer depends on the winding of the skin triangles, which the faces of a tetrahedron mix.
- New `Face growth` option (`OpenModelViewer.pick.setGrowth`): `Same normal` (default) measures the angle against the clicked face, so the selection stops where a curved surface bends away from it; `Smooth surface` keeps the previous behaviour (angle against the face it is reached from), which follows a curved surface. On a CAD surface mesh the selection stays inside the clicked CAD face in `Same normal` mode.
- The fatigue analysis is a separate shared library, `OpenModel::Fatigue` (`OpenModelFatigue`), with its sources, headers and tests in `fatigue/`. It links the shared core; the core library no longer contains it. Option `OPENMODEL_BUILD_FATIGUE` (default ON, needs `OPENMODEL_BUILD_SHARED`). The same directory builds on its own against an installed OpenModel package (`cmake -S fatigue -B build -DCMAKE_PREFIX_PATH=<prefix>`). Header paths (`<OpenModel/Fatigue/...>`) and test names are unchanged.

- Gmsh structured meshing for any hexahedral block, not only swept prisms: transfinite curves, surfaces and volume give regular grids of hexahedra or tetrahedra, touching blocks stay conformal, and swept solids support all four families (`StructuredElementShape::Hexahedron`, `Prism`, `Tetrahedron`, `Mixed`). New `MeshingOptions::structuredGmsh` (`StructuredGmshOptions`): transfinite curve distribution and coefficient, surface arrangement and the recombination settings (`Mesh.RecombinationAlgorithm`, `setRecombine` angle, `Mesh.RecombineOptimizeTopology`, `Mesh.RecombineNodeRepositioning`, `Mesh.RecombineMinimumQuality`). ## [0.1.0] - 2026-11-11

First release of OpenModel. This entry is the starting point of the changelog: it lists what the release contains.
The project was developed before under the name MeshGen; the notes of that work are kept in
[`docs/DEVELOPMENT_LOG.md`](docs/DEVELOPMENT_LOG.md).

### Added

**Mesh core**
- `MeshData`: nodes, linear and quadratic elements, element blocks, node sets and physical groups.
- Topology (faces, edges, boundary and internal classification, material interfaces), geometric validation and non-manifold diagnostics.
- Element quality metrics (`computeMeshQuality`), surface meshes (`SurfaceMesh`) and surface refinement (`SurfaceRefiner`).

**Mesh and model formats**
- Abaqus / CalculiX `.inp` reader and writer.
- code_aster `.mail` reader and writer.
- Compact binary mesh format **MGMB** ([`docs/MGMB_FORMAT.md`](docs/MGMB_FORMAT.md)).
- glTF / GLB export with PBR materials.
- Single-file viewer container **MGWV** ([`docs/MGWV_FORMAT.md`](docs/MGWV_FORMAT.md)).

**CAD and meshing backends (optional, off by default)**
- Gmsh surface and volume meshing: unstructured tetrahedra, structured hexahedra and prisms by sweeping straight prismatic solids, second-order elements, thin-face size control.
- Open CASCADE import of STEP, IGES and BREP, including assemblies, XDE layers and named sub-shapes.
- TetGen and Netgen volume meshing, MFEM mesh adapter.
- Assimp import of general 3D formats, with surface meshing and geometric group selectors (plane, normal, box, cylinder, sphere, cone) that create no CAD identities.

**CAD to FEM groups**
- Named CAD groups and user-defined B-Rep face groups carried onto the mesh as dimension-2 groups, mapped by Gmsh at meshing time or afterwards by geometry (`mapCADFacesToMesh`); a group is created whole or not at all.
- User face groups stored in an `.omgroups` sidecar next to the CAD file ([`docs/cad-face-groups-phase-4.md`](docs/cad-face-groups-phase-4.md)).

**FEM results and viewer**
- Result readers for CalculiX `.frd` and `.dat`, code_aster `.tab` tables and CSV: displacements, stresses, strains, principal and von Mises values, modal frequencies and mode shapes ([`docs/FEM_RESULTS.md`](docs/FEM_RESULTS.md)).
- Binding of results to a mesh, with a coordinate check.
- WebGL viewer: colour fields, deformed shape, modal animation, section plane and GPU picking of nodes, elements and faces.

**Analysis and solvers**
- Analysis script (`material`, `fix`, `force`, `pressure`, `step static` / `step frequency`) with the selectors `all`, `group:NAME` and `plane:x|y|z=VALUE`, and groups created by picking in the viewer ([`docs/SOLVER.md`](docs/SOLVER.md)).
- Complete CalculiX input writer and a solver runner that works in the background with live log and cancel (POSIX only).
- code_aster case export (`.mail`, `.comm`, `.export`) and launcher support ([`docs/CODE_ASTER.md`](docs/CODE_ASTER.md)).

**Fatigue module (library)**
- `OpenModel::Fatigue`: stress history from FEM results, Rainflow cycle counting, S–N and strain-life damage, Palmgren–Miner and Wang–Brown models, mean-stress corrections, local strain correction, operating spectra, reports and damage maps for the viewer ([manual](docs/fatigue/index.html)).

**Project manifest (library)**
- `OpenModelProject`: an `.omproj` document indexing project assets with relative paths and SHA-256 and size verification ([`docs/PROJECT_PERSISTENCE.md`](docs/PROJECT_PERSISTENCE.md)).

**Command-line tool `openmodel`**
- `--version`, `info`, `validate-demo`, `demo-inp`, `demo-gltf`, `demo-glb`, `demo-web`, `export-web`, `results-info`, `write-input`, `solve`, `export-aster`, `solve-aster`, `export-mail`, and `mesh-volume` when built with Gmsh.

**Desktop workbench `openmodel-webui` (optional, English interface)**
- CAD and model import, volume meshing, mesh and result loading, selection and groups (FEM and CAD face groups), analysis editing, solver run with live status and cancel, mesh validation, export to MGMB, INP, MGWV and GLB.

**Build, packaging and quality**
- CMake package `OpenModel` with the targets `OpenModel::Core` and `OpenModel::Shared`, installable and usable with `find_package`.
- Version configurable in one place, the `OPENMODEL_VERSION` CMake option, and exposed to programs through the generated `<OpenModel/Version.hpp>` (`OpenModel::version()`, `OpenModel::versionString()`, `OPENMODEL_VERSION_*` macros).
- CPack ZIP and TGZ packages, GitHub Actions workflows for CI (Linux GCC and Windows MSVC) and for tagged releases.
- 67 CTest tests in the default configuration, plus opt-in browser tests of the viewer and manual GUI end-to-end scripts.
- HTML manual ([`docs/index.html`](docs/index.html)) and fatigue manual.
- MIT license.

### Known limitations
- The CalculiX input and the code_aster export have not been run through the real solvers; the tests use stand-ins and check the plumbing, not the physics.
- The solver runner is POSIX only; the workbench was built and tested only on Linux.
- The fatigue module and the project manifest are libraries: neither is used by the CLI or the workbench yet.
- See [Status and known limits](README.md#status-and-known-limits) in the README for the full list.
