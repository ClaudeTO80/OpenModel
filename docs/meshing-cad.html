CAD and mesh generation

How OpenModel separates CAD geometry, tessellation and backend-specific mesh generation.

CAD model abstraction

CADModel is the geometry-facing abstraction; optional adapters provide native implementations. Open CASCADE support handles STEP, IGES and BREP-oriented CAD workflows and can preserve assembly/component structure. Assimp is an optional importer for general 3D assets; it is not a replacement for a parametric solid-kernel model.

Mesher interface

The abstract Mesher receives a CAD model and MeshingOptions, then populates a MeshData. Current optional backends include Gmsh, TetGen and Netgen, while MFEM provides a mesh adapter. A backend is only usable when its CMake option is enabled and its external SDK is correctly installed.

Meshing controls

OptionMeaning
dimensionSurface or volume mesh request.
elementSizeLegacy target size; retained for compatibility.
orderLinear (1) or quadratic (2), subject to backend support.
linearDeflectionChordal approximation tolerance for CAD tessellation; not a guaranteed edge length.
angularDeflectionAngular tessellation control (radians for Open CASCADE).
minElementSize, maxElementSizeOptional size bounds.
curvatureAdaptationAllow backends to refine more strongly in curved regions.
interfaceModeIndependent or conformal meshing across touching solids.
importCadGroupsMap CAD components and faces into physical groups when supported.

Why curvature matters

A curved CAD boundary is approximated by planar or polynomial finite elements. For a circular arc of radius R approximated by a chord of length h, the sagitta (maximum radial deviation) is

δ = R − √(R² − (h/2)²) ≈ h²/(8R), for h/R ≪ 1.

This explains why a fixed chord length produces larger geometric error on tighter curvature. Curvature-adaptive meshing attempts to reduce element size where curvature is high. The exact size field and guarantees are backend-dependent; linearDeflection should not be read as a strict global element-size bound.

Independent versus conformal interfaces

With independent meshing, two solids may have geometrically touching faces but unrelated surface triangulations and distinct node IDs. With conformal meshing, touching components share a common interface discretization and shared nodes. Conformity is important when a solver is expected to transfer displacement and traction continuously across a bonded interface without a contact formulation. A backend that cannot honor the requested mode should report that fact; the option is not a universal guarantee.

Physical groups from CAD

CAD assemblies and named faces can become physical groups. In the Gmsh adapter, group association is geometric: sample points from generated mesh entities are tested against CAD solids/faces and their adjacency. This allows group mapping to survive some geometry-fragment operations, but it is still a geometric matching procedure and should be checked on complex assemblies.

Recommended workflow

  1. Import CAD and inspect its solids, faces and assembly hierarchy.
  2. Choose surface/volume dimension, order and a size policy consistent with feature scale and curvature.
  3. Choose independent or conformal interfaces based on the intended structural connection.
  4. Generate the mesh and inspect backend diagnostics.
  5. Run MeshData::validate() and MeshValidator::validate(); inspect topology reports for open or non-manifold boundaries.
  6. Verify physical groups before using them for supports, forces or pressure loads.

Backend status

The core repository includes adapters, but each is optional. The README notes that not all optional backends were compiled in the latest test environment. Treat successful compilation and integration tests against the exact SDK version as prerequisites for production use.
