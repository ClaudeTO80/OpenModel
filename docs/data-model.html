Mesh data model

Understand the stable identifiers, compact connectivity representation, element blocks and semantic groups used by MeshData.

Design principles

MeshData is a solver-neutral in-memory description of a discretized domain. It stores geometry and topology, not constitutive laws, boundary conditions, solver state or result values. This keeps the mesh reusable across multiple analyses and tools.

Nodes: external IDs versus internal indices

A node has a stable external NodeId (64-bit unsigned integer) and a coordinate triple. The implementation stores IDs in mesh order, coordinates as packed triples of doubles, and an ID-to-index hash map.

NodeId id = mesh.nodeId(index);
NodeIndex index = mesh.nodeIndex(id);
auto xyz = mesh.nodeCoordinates(index);

External IDs preserve identifiers from solver and interchange files. Internal indices are zero-based positions used by connectivity arrays. They are not interchangeable. A result importer must resolve a result record by external ID, never assume that record row i refers to internal node index i.

Element blocks

An ElementBlock groups elements that share one topological type and one node count. It stores element IDs and flattened connectivity. Connectivity entries are internal NodeIndex values. The element catalog includes Point1; Line2/3; Triangle3/6; Quadrilateral4/8/9; Tetrahedron4/10; Hexahedron8/20/27; Prism6/15; and Pyramid5.

Element dimensionTypesGeometric role
0Point1Point entity.
1Line2, Line3Curve/edge discretization.
2Triangle, quadrilateral variantsSurface patches and boundary descriptions.
3Tetrahedron, hexahedron, prism, pyramidVolume discretization.

The implementation intentionally keeps backend-specific numeric element codes out of the core. Importers map a source format's element identifier to ElementType.

Node sets and physical groups

Node sets are named collections of internal node indices. They are useful for supports and node-based selectors. Physical groups carry a name, topological dimension, tag, element IDs and optional material-name metadata. A dimension-3 group commonly identifies a volume region; dimension-2 groups identify surfaces or boundary patches.

materialName is metadata only. It does not create a material law or assign constitutive properties. Material and analysis parameters are introduced later through AnalysisModel.

Structural invariants

  • Node IDs are unique and mapped consistently.
  • Coordinate storage contains exactly three doubles per node.
  • Each block's connectivity length is element_count × nodes_per_element.
  • Every connectivity index refers to an existing node.
  • Element topology and node count agree where the topology has a known fixed count.
  • Node-set indices and physical-group element references must be valid.

MeshData::validate() checks structural consistency. MeshValidator::validate() performs additional geometric checks; these are separate responsibilities.

Import transaction

The public MeshImporter interface uses a polymorphic reader contract. The Abaqus and CalculiX importers parse into temporary data and replace the destination only after parsing and structural validation succeed. Failure therefore does not leave a half-imported mesh in the caller's object. Diagnostics include a status, code, message and optional source line.

Minimal construction example

OpenModel::MeshData mesh;
const auto n0 = mesh.addNode(10, 0.0, 0.0, 0.0);
const auto n1 = mesh.addNode(20, 1.0, 0.0, 0.0);
const auto n2 = mesh.addNode(30, 0.0, 1.0, 0.0);
mesh.addElement("surface", ElementType::Triangle3, 100, {n0,n1,n2});
mesh.addNodeSet("corner", {n0});
mesh.addPhysicalGroup("plate-skin", 2, 1, {100});

The snippet illustrates the data model; production code should check exceptions and the result of subsequent validation.
