Multiaxial cycle-counting contract

Multiaxial fatigue cannot be obtained reliably by independently counting tensor components or by applying scalar Rainflow to von Mises stress. The branch therefore preserves the ordered tensor path and defines a contract for future algorithms.

1. Why scalar reduction is not a general multiaxial solution

A multiaxial history is a path in the space of symmetric tensors:

\[\mathcal{P}:t\longmapsto\boldsymbol{\sigma}(t)\in\mathrm{Sym}(3).\]

Two histories can have the same von Mises scalar range but different principal directions, phase relationships and shear/normal coupling. A scalar invariant discards this information. Likewise, separate component Rainflow counts do not necessarily identify physically equivalent closed cycles in tensor space.

2. Path-based cycle representation

MultiaxialLoadCycle stores indices into the original StressHistory, a closed/open flag, a positive count weight, a closure residual and a stable method identifier. The path is not copied into a reduced scalar sequence. It can therefore recover time, full tensor, source step, raw solver sample, unit and provenance.

3. Tensor closure

For endpoint tensors \(\mathbf{T}_a\) and \(\mathbf{T}_b\), the current contract computes the Frobenius distance:

\[\delta_{\mathrm{cl}}= \|\mathbf{T}_a-\mathbf{T}_b\|_F =\sqrt{\sum_{i=1}^{3}\sum_{j=1}^{3} (T_{a,ij}-T_{b,ij})^2}.\]

A cycle marked closed is accepted only if

\[\delta_{\mathrm{cl}}\leq\varepsilon_{\mathrm{cl}},\]

where \(\varepsilon_{\mathrm{cl}}\) is a finite, non-negative absolute tolerance expressed in the history's stress or strain unit. No SI conversion or scale normalization is performed. An open path does not need to satisfy endpoint closure, but its residual is still reported.

4. Extension interface

IMultiaxialCycleCounter is the polymorphic interface for future critical-plane, path-based or invariant-based counting algorithms. A conforming implementation must validate its assumptions, preserve path sample references, identify its method, and document closure, filtering, turning-point and cycle-weight conventions.

5. Implementation status

Important: this branch provides MultiaxialCycleContract and IMultiaxialCycleCounter, not a concrete multiaxial counting method. No Wang–Brown, Findley, Fatemi–Socie, Brown–Miller, Dang Van, or other criterion is implemented by this contract alone. Do not interpret the presence of the interface as a validated multiaxial fatigue capability.

The scalar uniaxial workflows remain available through explicit directional projection and scalar Rainflow. A future multiaxial damage model must consume the complete cycle path and a clearly specified material criterion; it must not silently substitute equivalent-stress range.
