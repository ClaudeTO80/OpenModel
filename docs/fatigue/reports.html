Spectrum reports and damage maps

The reporting layer evaluates fatigue independently at selected FEM result positions, retains failures explicitly, serializes audit-friendly CSV/JSON and maps result positions to mesh coordinates without inventing locations.

1. Multi-position S–N reports

FatigueReportBuilder runs one complete uniaxial stress-life analysis for each supplied FatiguePositionInput. Each position carries an explicit material pointer, projection direction and optional label. Materials are not inferred from element IDs, physical groups or solver input decks.

Each row has a separate hasDamage flag. A failed read or calculation is not a zero-damage result. Report status distinguishes complete success, partial failure and all-position failure. The maximum-damage index refers to the original input order and is valid only when hasMaximumDamage is true.

2. Spectrum reports at each position

FatigueSpectrumReportBuilder evaluates a separate ordered load spectrum for each position. A position and material are fixed for all its blocks; each block may specify its own source, field, projection and repetition count.

\[D_p=\sum_{b=1}^{B}r_bD_{p,b},\]

where \(p\) identifies one material point, \(D_{p,b}\) is damage from one block, and \(r_b\) is the number of block occurrences in one spectrum repetition. Damage is never summed across different FEM positions: each point has its own fatigue damage and nominal life.

3. CSV and JSON serialization

FatigueReportWriter writes to caller-owned streams and does not open files or choose paths.

WriterContents
writeCsvSummaryOne row per selected position, including failed rows.
writeCsvCyclesOne row per counted cycle, retaining position and original sample indices.
writeJsonopenmodel.fatigue-report.v1; cycle arrays optional.
writeCsvSpectrumSummaryOne row per position with spectrum damage/life.
writeCsvSpectrumBlocksOne row per evaluated block with repetition and contribution.
writeSpectrumJsonopenmodel.fatigue-spectrum-report.v1.
writeDamageMapCsv/JsonDamage-map entries; JSON schema openmodel.fatigue-damage-map.v1.

Failed rows remain present. Missing damage/life values are empty CSV fields or JSON null, never fabricated zeros. Non-finite JSON numeric values are encoded as null. Raw tensor histories are not serialized by the current report schema; they remain in memory within each analysis result.

4. Mapping result positions to mesh coordinates

Result positionCoordinate policy
NodeExact mesh node coordinates matched by external node ID.
ElementArithmetic centroid of all nodes in the element connectivity, matched by external element ID.
Integration pointUnavailable; the current mesh model does not store solver integration-point coordinates or evaluate shape functions at imported IP locations.

For an element with \(n_e\) connectivity nodes, the reported centroid is

\[\mathbf{x}_c=\frac{1}{n_e}\sum_{a=1}^{n_e}\mathbf{x}_a.\]

This is the arithmetic centroid of the listed mesh nodes. For higher-order elements it is not necessarily the geometric centroid of the curved isoparametric element.

The damage map is a transfer structure, not an interpolation algorithm. It does not extrapolate element damage to nodes, average integration-point values, or substitute an element centroid for an integration point. Entries without coordinates remain explicitly unavailable.

5. WebGL element-field adapter

FatigueDamageMapWebViewAdapter::makeElementField accepts element positions only. It requires one finite, non-negative damage value for every mesh element, rejects duplicate IDs and incomplete coverage, and preserves the mesh's global element order (block by block). It does not synthesize values for failed rows or collapse nodal/integration-point data into element data.

6. Example

const auto report = FatigueSpectrumReportBuilder::build(
    positionInputs, temperatureKelvin);

std::ofstream json("fatigue-spectrum.json");
auto written = FatigueReportWriter::writeSpectrumJson(
    report, json, true); // include cycle detail

const auto map = FatigueDamageMapBuilder::build(report, mesh);
