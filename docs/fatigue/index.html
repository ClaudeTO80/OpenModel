Fatigue analysis

A solver-neutral fatigue post-processing module for OpenModel. It reads exact FEM result samples, preserves the full stress tensor and its provenance, counts uniaxial cycles, evaluates stress-life or strain-life damage, and produces traceable reports.

Branch scope. This manual describes feature/fatigue-result-contract, not the default main branch. The module is C++17. CalculiX is one possible source of FEM results, but the fatigue algorithms consume IResultSource rather than parsing solver files themselves.

Pipeline overview

  1. Obtain a solver-neutral result source with explicit step semantics and external entity IDs.
  2. Read the requested field at one exact node, element or integration point for every time step.
  3. Normalize component labels, shear convention and coordinate frame.
  4. Retain a complete ordered tensor history with source references and metadata.
  5. Project the tensor onto an explicitly supplied direction for current uniaxial workflows.
  6. Count scalar cycles, evaluate material life and accumulate damage.
  7. Retain intermediate data so high-damage cycles can be traced to original FEM samples.

Capability boundary

The current scalar Rainflow counter is not a multiaxial fatigue algorithm. The multiaxial API is a data/validation contract and extension point; it does not implement Wang–Brown, critical-plane or invariant-based counting. The strain-life path is uniaxial and does not perform incremental cyclic plasticity.
