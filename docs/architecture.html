Adding an importer

  1. Implement the relevant abstract reader contract (MeshImporter for meshes or ResultImporter for results).
  2. Map source-specific element codes and component labels into solver-neutral OpenModel types.
  3. Preserve external IDs and never assume source record order matches internal storage order.
  4. Parse into temporary destination state and publish only after successful validation.
  5. Return structured diagnostics for unsupported features; do not silently coerce topology or discard scientifically meaningful data.
  6. Add positive, negative, malformed-input and round-trip tests with small fixtures.

CLI and workbench

The openmodel CLI exposes information, demo generation, validation, mesh/result export, result inspection, solver input generation and solver launch. The optional openmodel-webui desktop application uses WebUI and an embedded HTML/JavaScript interface with a WebGL viewer. The web viewer can display scalar fields, deformation, modal animation, section planes and GPU picking for nodes/elements/faces. It does not replace the native mesh model or solver.

Tests and what they establish

The test suite covers core data structures, binary I/O, importers, validation, topology, group handling, writers, result import/binding, CLI plumbing and headless browser behavior. Some integration tests are conditional on external SDKs and tools. A passing test means the tested behavior works for the fixture and environment; it does not automatically establish solver physics, all format dialects, or production performance.

Known limits on the inspected main branch

  • Project status is early (version 0.1.0); former MeshGen phase numbering is historical.
  • Solver deck generation has not been verified by a real CalculiX run in the latest documented environment.
  • ProcessRunner is POSIX-only; Windows solver execution is not implemented.
  • Analysis supports one isotropic linear-elastic material and one static or frequency step; no contact or nonlinear constitutive laws.
  • Equal nodal force sharing is not a consistent load vector for quadratic elements.
  • Integration-point result data are not preserved as native result fields; DAT element output is averaged per element with a warning.
  • Several mesh importer keywords and result formats are not supported, as listed in the relevant chapters.
  • Optional backends require separate SDKs and may not have been built in the latest test environment.

Reproducible engineering practice

Record units, solver and backend versions, mesh provenance, analysis-script text and result-file names. Keep the original solver output. Validate imported geometry and groups before applying loads. Compare representative cases against analytical solutions or independently verified solver runs before relying on computed quantities for design decisions.
