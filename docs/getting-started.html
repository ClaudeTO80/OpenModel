Getting started

Build OpenModel, use the command-line interface, and link the installed C++ library into an application.

Requirements

  • A C++17 compiler.
  • CMake 3.20 or newer.
  • POSIX threads.
  • Optional: Python 3 for fixture-generation tests; Node.js and Playwright for browser tests; native SDKs for optional backends.

Build from source

git clone https://github.com/ClaudeTO80/OpenModel.git
cd OpenModel
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DOPENMODEL_BUILD_TESTS=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure

On multi-configuration generators such as Visual Studio, omit CMAKE_BUILD_TYPE and select the configuration at build time, for example cmake --build build --config Release.

CMake options

OptionDefault / purpose
OPENMODEL_VERSION0.1.2; MAJOR.MINOR.PATCH of the build. It sets the installed package version and the generated <OpenModel/Version.hpp> (OpenModel::version(), OpenModel::versionString()); the CLI prints it with openmodel --version.
OPENMODEL_BUILD_TESTSON; build CTest suite.
OPENMODEL_BUILD_CLION; build openmodel.
OPENMODEL_BUILD_SHAREDON; build shared library in addition to static core.
OPENMODEL_BUILD_WEBUIOFF; desktop workbench, requires WebUI SDK.
OPENMODEL_BUILD_BENCHMARKSOFF; build synthetic benchmarks.
OPENMODEL_BUILD_GMSH_BACKENDOFF; Gmsh mesher.
OPENMODEL_BUILD_OCC_BACKENDOFF; Open CASCADE CAD backend.
OPENMODEL_BUILD_ASSIMP_BACKENDOFF; Assimp model importer.
OPENMODEL_BUILD_TETGEN_BACKENDOFF; TetGen backend.
OPENMODEL_BUILD_NETGEN_BACKENDOFF; Netgen backend.
OPENMODEL_BUILD_MFEM_BACKENDOFF; MFEM adapter.

Optional backends are separate build targets and require their own SDK/library installations. They are not part of the minimal core dependency set.

Try the CLI

openmodel info
openmodel validate-demo
openmodel demo-inp demo.inp
openmodel demo-web demo.mgwv 12
openmodel export-web beam.inp beam.mgwv --results beam.frd --results beam.dat
openmodel results-info beam.frd
openmodel write-input beam.inp analysis.txt job.inp
openmodel solve beam.inp analysis.txt job-directory --solver /path/to/ccx

demo-web creates a viewer-oriented sample. Open examples/webgl-fem-viewer/index.html in a browser and load the resulting MGWV file. The viewer is a separate HTML/JavaScript application; it does not execute the finite-element solution.

Use the installed CMake package

cmake --install build --prefix /opt/openmodel

Consumer CMakeLists.txt:

find_package(OpenModel 0.1 CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE OpenModel::Core)

Minimal C++ example:

#include <OpenModel/MeshData.hpp>
#include <OpenModel/MeshImporter.hpp>

int main() {
    OpenModel::MeshData mesh;
    OpenModel::AbaqusInpImporter reader;
    const auto result = reader.read("model.inp", mesh);
    if (!result) return 1;
    return mesh.validate().empty() ? 0 : 2;
}

Set CMAKE_PREFIX_PATH or OpenModel_DIR if the installation prefix is non-standard. See examples/cmake-consumer.

Desktop workbench

Configure with -DOPENMODEL_BUILD_WEBUI=ON -DOPENMODEL_WEBUI_ROOT=/path/to/webui-sdk. The WebUI SDK is not vendored. A Chromium-based browser is required at runtime. The workbench interface is in English.

Build and verification caveats

The repository's README reports Linux as the latest tested environment. The solver process runner is POSIX-only and reports an error on Windows. Optional geometry/meshing adapters are not necessarily compiled in the default CI/test environment. Do not infer backend availability merely because its public header exists.
